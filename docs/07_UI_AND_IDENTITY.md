## 1. Who uses it, and for what

| Question | Answer |
|---|---|
| Users | Clinic administrators and staff who use the Dafira platform (domain profile, `intended_users`) |
| Primary jobs (Phase 6) | Keep the assistant's library of Dafira documents correct: add documents, follow their processing, add new versions, choose which version the assistant uses, remove outdated ones |
| Primary job (Phases 9–10) | Ask questions and check the sources of each answer |
| Context | One person on their own Windows machine, in Arabic, often between other tasks. Mistakes in the library silently change future answers, so **state must always be visible** and **destructive actions must be deliberate** |

## 2. Identity concept: the braid

«ضفيرة» means *braid*. Arabic calligraphy has a real style built on the same idea, **braided Kufic** (الكوفي المضفور), where letter strokes interlace. The identity takes both:

- **The mark** is a three-strand plait. Each strand passes over, then under, the next, like a real braid; a twisted rope keeps one strand in front, so it would be the wrong image. The three strands stand for the three things the assistant weaves together: **documents, questions, and answers with their sources**.
- **Headings use a Kufic typeface** (Noto Kufi Arabic), the type-world echo of braided Kufic.

### Where the braid appears (and only there)

| Place | Why |
|---|---|
| Header mark and favicon | Brand recognition |
| **Processing indicator**: the plait slowly weaves while a document is waiting or being processed | The one bold, memorable element. It also means something: the document is being woven into the assistant's knowledge |
| A thin plait rule on the home page, under the welcome text | Quiet brand presence on the landing page |
| The empty library | Friendly emptiness without stock illustrations |

Everything else is deliberately quiet: no gradients, no decorative cards, no motion except the weave and the drag-over highlight. Motion respects `prefers-reduced-motion`.

The mark is **generated by code** (`tools/brand/make_braid.py`): three sine waves a third of a period apart, split at their crossings, drawn back-to-front with a paper-coloured halo. Regenerate it after changing a colour:

```bash
python tools/brand/make_braid.py
```

## 3. Colour

Three strand colours carry meaning; neutrals carry the text. Medical software often defaults to teal-on-white. Here, teal is only one of three strands, and it is reserved for "ready / approved".

| Token | Hex | Role |
|---|---|---|
| `--ink` | `#18233F` | Text (deep indigo-navy, never pure black) |
| `--ink-soft` | `#4A5572` | Secondary text and labels |
| `--paper` | `#F6F7FB` | Page background (cool, slightly blue) |
| `--surface` | `#FFFFFF` | Raised areas: table, panels, versions |
| `--indigo` | `#3346A0` | **Strand 1: actions and links** |
| `--teal` | `#17766A` | **Strand 2: ready, approved for answers** |
| `--saffron` | `#D99A1E` | **Strand 3: brand and "in progress"** (graphics only) |
| `--danger` | `#B3261E` | Failure and destructive actions |

### Measured contrast (WCAG 2.2)

All text meets **AA (≥ 4.5:1)**. Saffron (2.4:1 on white) is never used for text; its text variant `--saffron-ink` is.

| Pair | Ratio |
|---|---|
| Ink on paper | 14.5 |
| Secondary text on paper | 6.9 |
| White on indigo (primary button) | 8.3 |
| Indigo link on white | 8.3 |
| "Ready" teal on its wash | 4.7 |
| "In progress" saffron-ink on its wash | 6.3 |
| Danger on its wash | 5.6 |
| Focus ring (indigo) on paper | 7.8 |

Status is never shown by colour alone: every badge has a text label (جاهز، قيد المعالجة، تعذّرت المعالجة …), and the processing badge also has the weaving mark.

## 4. Typography

| Role | Typeface | Why |
|---|---|---|
| Headings, wordmark, version titles | **Noto Kufi Arabic** (variable) | Geometric Kufic: the link to braided Kufic; clear at large sizes |
| Text, tables, buttons, forms | **IBM Plex Sans Arabic** 400 / 500 / 600 | Designed for interfaces; open, readable Naskh-influenced forms at small sizes; matching Latin for "PDF", "Markdown", file names |

- **Scale:** ratio 1.25 from 16 px (13 · 16 · 20 · 25 · 31 · 39 px).
- **Line height:** 1.75 for Arabic text and 1.45 for headings. Arabic needs more vertical room than Latin for its ascenders, descenders, and dots.
- **Line length:** at most about 68 characters (`--measure`).
- **No all-caps or letter-spacing tricks:** they do not exist in Arabic.
- **Numbers:** Western digits, with `tabular-nums` in tables so sizes and dates line up.
- **Self-hosted:** WOFF2, Arabic and Latin subsets only (≈ 400 KB in total, served from the app). Nothing is loaded from the internet, so the app works offline and no third party sees page views. Licences: SIL OFL 1.1, stored next to the files.

## 5. Layout and components

```text
┌──────────────────────────────────────────────────────────────┐
│  المستندات  الرئيسية                      ضفيرة  [braid mark] │  header (RTL: brand at the start)
├──────────────────────────────────────────────────────────────┤
│  [alerts region: one place for every success and error]      │
│                                              مكتبة المستندات  │  page title (Kufi)
│  ┌ upload: icon · text · [اختيار ملف] [رفع المستند] ─────────┐ │  drag and drop, checks, progress
│  └──────────────────────────────────────────────────────────┘ │
│  المستند │ الحالة │ النسخة المعتمدة │ الحجم │ آخر تحديث       │  a real table (not cards)
└──────────────────────────────────────────────────────────────┘

Document details
┌──────────────────────────────┬───────────────────────────────┐
│  سجل النسخ (timeline)    ●    │  رفع نسخة جديدة              │
│  ┌ النسخة 2 · جاهز · معتمدة ┐ │  note: current version stays  │
│  └──────────────────────────┘ │        approved until ready   │
│  ┌ النسخة 1 · [اعتماد] [حذف]┐ ○ │  حذف المستند (danger panel)   │
└──────────────────────────────┴───────────────────────────────┘
```

| Component | Decision | Reason |
|---|---|---|
| Library | A semantic `<table>` with column headers; becomes labelled rows on phones | Documents are records to compare; screen readers announce headers |
| Status | Badge with text; the weave while waiting or processing; the current stage under it | FR-ING-02: progress is visible |
| Mixed state | "تعذّرت المعالجة — للنسخة 2، وتبقى النسخة 1 معتمدة" | A failed new version must not look like a broken document |
| Version history | A timeline, newest first. One thread joins the versions; the approved one is a filled teal node | Versions really are a sequence, so numbering and a line are information, not decoration |
| Approve / retry / delete | Shown only when allowed (approve: ready and not approved; retry: failed; delete: not approved) | Prevents error messages by not offering impossible actions; the server still enforces the rules |
| Confirmation | An accessible `<dialog>`; the confirm button repeats the action's name ("حذف المستند"); focus starts on «إلغاء» | Destructive actions are deliberate. Escape cancels |
| Alerts | One `#alerts` region (`aria-live`). Server errors are rendered there in Arabic, whatever triggered them | Consistent feedback; no silent failures |
| Upload | Drag and drop or button; type and size checked in the browser first; progress bar; the form resets after success | Fast feedback; the server repeats every check |

### Writing rules for interface text
- Verbs say what happens: «رفع المستند», «اعتماد هذه النسخة», «حذف النسخة». The confirmation and success messages reuse the same verb («اعتُمدت النسخة 1…»).
- Errors say what happened and what to do, and never apologise.
- Users' words, not system words: «النسخة المعتمدة في الإجابات», not "active version id"; «تعذّرت المعالجة», not "failed".
- Arabic number agreement is applied («مستند واحد، مستندان، 3 مستندات، 11 مستنداً») by `web/ui/format.py`.

## 6. Interaction model (HTMX)

| Behaviour | How |
|---|---|
| Live status | The library and the details block poll every 2 s **only while** something is waiting or processing; polling stops by itself (FR-UI-03) |
| Actions | Each action returns the updated block, plus an out-of-band alert |
| Errors | Error responses keep their HTTP status. HTMX requests receive an Arabic alert fragment with `HX-Retarget: #alerts` |
| Navigation after deletion | `HX-Redirect` back to the library, which shows «حُذف «…».» |
| No inline JavaScript | All behaviour is in `static/app.js` (event listeners), so the Content-Security-Policy can forbid inline script |
